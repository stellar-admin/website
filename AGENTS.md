# StellarAdmin website contributor guidance

This independent repository contains the public documentation site at https://www.stellaradmin.com, built with TanStack Start and Fumadocs. It remains separate from the StellarAdmin product repository. Start website sessions here; ordinary website development requires no workspace or product checkout. Read [README.md](README.md) for the application structure.

## Setup and verification

Use pnpm as pinned in `package.json` and the checked-in lockfile. Do not introduce another package manager lockfile.

```bash
pnpm install --frozen-lockfile
pnpm dev
pnpm lint
pnpm types:check
pnpm build
```

For application or MDX changes, run lint, type checking, and the production build; inspect affected pages. Formatting uses oxfmt and linting uses oxlint. Format only touched files. Preserve each file's encoding, BOM, and line endings. Write one line per Markdown/MDX prose paragraph; do not hard-wrap or reflow untouched prose.

## Content and exports

Write public documentation in `content/docs/` with navigation in `meta.json`. Follow existing component pages for `<Demo>`, `<include>`, and API tables. Keep prose focused on consumer behavior and use the Voyager Travel theme for sample content.

`public/demo/` and snippets under `content/docs/tag-helpers/components/_include/` are generated by the separate product repository's `docs/DocsSamplesGenerator`. Change samples or the generator there; do not hand-edit generated exports. Export work requires a product checkout, but the website build consumes the checked-in outputs without running .NET. The exporter defaults to a sibling website checkout; `STELLARADMIN_WEBSITE_DIR` selects a different destination.

Reusable inline-example code lives in `src/components/inline-example/`. `pnpm examples:export` refreshes its fragments, scoped styles, and runtime manifest from existing docs exports; it is not part of `pnpm build`. Use the product-owned [inline example workflow](https://github.com/stellar-admin/stellar-admin/blob/master/docs/design/inline-website-examples.md) and [embedding skill](https://github.com/stellar-admin/stellar-admin/blob/master/.agents/skills/embed-website-components/SKILL.md) when changing that integration. During local development, these same paths are available in a product checkout. Read that repository's `AGENTS.md` before editing product sources.

## Working agreement

Follow the user's current scope and authorization. Preserve existing edits and inspect Git status before changes or generation. Do not commit, push, publish, or deploy unless authorized. Historical plans do not authorize work.

Inspect and report Git status separately for each affected repository. Concurrent work needs an isolated worktree per repository; coordinate exported outputs. A normalized generated diff is only a review aid and never permission to discard changes. Stop only processes you started; port 5205 belongs to Jerrie.

For substantial website-only work, keep handoff records under `docs/plans/` when needed. Cross-repo component work uses the product's indexed plan so decisions and verification have one maintained record. Shared product design and C# conventions stay in the product repository; website-only tasks follow this entry point.
