## Usage

The `sa-field` family of Tag Helpers are designed for composing accessible forms. `sa-field` is the core wrapper for a single field.

`sa-field-content` is a flex column that groups label and description. This component is useful when you use a field in horizontal orientation

## Explicit and implicit fields

The usage examples demonstrated so far require a lot of boilerplate when creating fields by specifying `sa-field`, `sa-field-label`, `sa-field-description`, etc. To improve the developer experience, all the StellarAdmin input controls such as `sa-input`, `sa-select`, `sa-textarea`, etc. can implicitly create fields using one of the following two techniques.

1. When using data binding (with the `asp-for` attribute), StellarAdmin will implicitly wrap the input inside a `sa-field` with the corresponding `sa-field-label` and `sa-field-description` inferred from data annotations. If your model contains errors related to the bound property, a `sa-field-error` component with the error message will also be added.

   ```razor
   <sa-input asp-for="Model.Name"/>
   ```

2. If you are not using data binding, you can also opt in to implicit fields by specifying any combination of the `label`, `description`, and `error` attributes. When doing this, your input will be wrapped inside a `sa-field` with the corresponding `sa-field-label`, `sa-field-description`, and `sa-field-error` automatically added.

   ```razor
   <sa-input label="First Name"
             description="First name as displayed on card"
             error="Enter the name exactly as it appears on the card"/>
   ```

In both cases mentioned above, you can opt out of implicit fields by setting the `render-field` attribute to `false`. In the example below, StellarAdmin will not create an implicit field, even though we're using model binding.

```razor
<sa-input render-field="false" asp-for="Model.Name"/>
```

Most of the examples in this document demonstrate both explicit and implicit mode. Notice how compact the implicit examples are compared to their explicit counterparts.

## Examples

### Implicit fields

Whenever you use any if the various field input Tag Helpers (such as `sa-input`, `sa-textarea`, `sa-select` etc.) along with data binding, StellarAdmin will implicitly create a field with a label, description, and placeholder for you. You can see this demonstrated in the example below which implements the same form as above, but using data binding.

<Demo src="/demo/tag-helpers/field-implicit.html">
<Tabs items={["Razor", "Model"]}>
    <Tab value="Razor">
      <include>./_include/field-implicit.mdx</include>
    </Tab>
    <Tab value="Model">
      ```cs
      public class ImplicitModel
      {
          [Display(
              Name = "Card Number",
              Description = "Enter your 16-digit card number",
              Prompt = "1234 5678 9012 3456"
          )]
          public string? CardNumber { get; set; }

          [Display(Name = "Comments", Prompt = "Add any additional comments")]
          public string? Comments { get; set; }

          [Display(Name = "CVV")]
          public string? Cvv { get; set; }

          [Display(Name = "Same as shipping address")]
          public bool IsBillingAddressSame { get; set; }

          public string? Month { get; set; }

          [Display(Name = "Name on Card", Prompt = "Ibn Battuta")]
          public string? Name { get; set; }

          public string? Year { get; set; }
      }
      ```
    </Tab>

  </Tabs>

</Demo>

### Field Group

Stack `sa-field` components with `sa-field-group`. Add `sa-field-separator` to divide them. When grouping checkboxes or radio buttons, you can add `data-slot="checkbox-group"` or `data-slot="radio-group"` to tighten up spacing between the individual inputs.

## API Reference

### `<sa-field>`

The `<sa-field>` tag helper renders a `<div>` element that wraps a single form
field. In addition to the attribute below, it forwards any standard [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes)
to the rendered element.

<TypeTable
  type={{
    orientation: {
      description: "The layout direction of the field.",
      type: "FieldOrientation",
      typeDescription:
        "FieldOrientation.Vertical | FieldOrientation.Horizontal | FieldOrientation.Responsive",
      default: "FieldOrientation.Vertical",
    },
  }}
/>

### `<sa-field-label>`

The `<sa-field-label>` tag helper renders a `<label>` element. In addition to
the attribute below, it forwards any standard [`<label>`
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/label#attributes)
(such as `for`) to the rendered element.

<TypeTable
  type={{
    "asp-for": {
      description:
        "An expression to be evaluated against the current model. When the tag has no content, the label text is inferred from the bound property's [Display] metadata.",
      type: "ModelExpression",
    },
  }}
/>

### `<sa-field-description>`

The `<sa-field-description>` tag helper renders a `<p>` element with help text
for a field, forwarding any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes).

<TypeTable
  type={{
    "asp-for": {
      description:
        "An expression to be evaluated against the current model. When the tag has no content, the description is inferred from the bound property's [Display] metadata; nothing is rendered if there is none.",
      type: "ModelExpression",
    },
  }}
/>

### `<sa-field-error>`

The `<sa-field-error>` tag helper renders a `<div>` element with
`role="alert"` that displays a validation message, forwarding any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes).
It is hidden unless a validation error is present.

<TypeTable
  type={{
    "asp-for": {
      description:
        "An expression to be evaluated against the current model. When the tag has no content, the validation message for the bound property is rendered.",
      type: "ModelExpression",
    },
  }}
/>

### `<sa-field-title>`

The `<sa-field-title>` tag helper renders a `<div>` element for a
non-`<label>` field title, forwarding any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes).

### `<sa-field-content>`

The `<sa-field-content>` tag helper renders a `<div>` element that groups the
label and description of a horizontal field, forwarding any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes).

### `<sa-field-group>`

The `<sa-field-group>` tag helper renders a `<div>` element that stacks
related fields, forwarding any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes).

### `<sa-field-separator>`

The `<sa-field-separator>` tag helper renders a `<div>` element containing a
horizontal separator, with any child content rendered as text on top of the
line. It forwards any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes).

### `<sa-field-set>`

The `<sa-field-set>` tag helper renders a `<fieldset>` element. It forwards
any standard [`<fieldset>`
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/fieldset#attributes)
(such as `disabled`, `form`, or `name`) to the rendered element.

### `<sa-field-legend>`

The `<sa-field-legend>` tag helper renders a `<legend>` element for a
`<sa-field-set>`. In addition to the attribute below, it forwards any [global
attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes)
to the rendered element.

<TypeTable
  type={{
    variant: {
      description: "The visual style of the legend.",
      type: "FieldLegendVariant",
      typeDescription: "FieldLegendVariant.Legend | FieldLegendVariant.Label",
      default: "FieldLegendVariant.Legend",
    },
  }}
/>
