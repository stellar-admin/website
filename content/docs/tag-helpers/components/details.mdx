## Usage

A details list is composed of `<sa-details>` wrapping one `<sa-display-field>` per value. Bind each field to a model property with `asp-for`: the label comes from the property's `[Display]` name, and the value is formatted from the property's metadata.

```razor
<sa-details columns="...">
    <sa-display-field asp-for="..." />
    <sa-display-field asp-for="..." />
</sa-details>
```

Inside `<sa-details>` the fields render as a description list, with each label in a `<dt>` and each value in a `<dd>`. A `<sa-display-field>` can also be used on its own, for example among the inputs of a form; it then renders `<div>` elements instead.

## Examples

### Columns and spans

Set `columns` to lay the fields out in a grid. The columns respond to the width of the list rather than the viewport, so the same markup works in a page, a card or a side panel. `columns` applies once the list is at least 40rem wide, and the list uses one column below that. Use `columns-sm`, `columns-md` and `columns-lg` to set the number of columns at 30rem, 40rem and 56rem; a width without a value uses the value of the next smaller width.

Set `column-span` on a field to span several columns, or `column-span-full` to span all of them. `column-span-sm`, `column-span-md` and `column-span-lg` set the span at each width in the same way, and a span is limited to the number of columns at each width.

### Empty values

A `null` value, a blank string or an empty collection shows a dash in a muted color. Set `empty-text` to show different text, or set `NullDisplayText` in the property's `[DisplayFormat]` attribute to use the same text wherever the property is displayed. Zero and `false` are values, not empty ones.

### Value types

Values are formatted from the property's metadata:

- The `format` attribute, or else the `DataFormatString` of the property's `[DisplayFormat]` attribute, formats numbers and dates.
- An enum value shows its member's `[Display]` name.
- A `bool` shows a check or a cross icon, with "Yes" or "No" for screen readers.
- An `[EmailAddress]` property links to a `mailto:` URL, and a `[Url]` property links to its URL when it is an `http` or `https` URL.
- `href` links the value to any URL.
- A collection shows its items separated by commas.
- A `[DataType(DataType.MultilineText)]` property keeps its line breaks.

### Templates and custom content

To render a value with your own markup, such as a badge for a status, set `template` to the name of a display template, or add a `[UIHint]` attribute to the property. The template is found like a partial view named `DisplayTemplates/{name}`, and its model is the value. Templates are only ever used by name: the built-in display templates for a type, such as the checkbox MVC renders for a `bool`, never apply. A template that cannot be found throws an exception.

Child content replaces the value entirely, and a field with a `label` and child content needs no `asp-for`. Set `secondary` to add muted text after the value.

<Demo src="/demo/tag-helpers/details-templates.html">
  <include>./_include/details-templates.mdx</include>
</Demo>

The status template in this example is a `DisplayTemplates/BookingStatus.cshtml` view:

```razor
@model BookingStatus
@{
    var variant = Model switch
    {
        BookingStatus.Cancelled => BadgeVariant.Destructive,
        BookingStatus.Pending => BadgeVariant.Secondary,
        _ => BadgeVariant.Default,
    };
}
<sa-badge variant="@variant">@Model.ToString()</sa-badge>
```

### Among form inputs

Place a `<sa-display-field>` among the inputs of a form to show a value that cannot be edited. Outside `<sa-details>` it takes the label style of an input and the height of a control, so a row of inputs and display fields lines up. A `<sa-details>` in its own [Form Section](form-section) shows information about the record, such as its audit history, below the inputs.
