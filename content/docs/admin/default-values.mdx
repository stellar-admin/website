---
title: Setting default values
description: Set the values a new record starts with
---

Before StellarAdmin displays the create page, it initializes the model the form edits. You can specify the default values by calling `UseFactory()` with a function that returns a new instance of the underlying model. The example below starts a departure six weeks away, with a meeting time of 9:00 and a status of `Scheduled`:

```cs
resource.AllowCreate(create =>
{
    create.UseFactory(() => new Departure
    {
        StartDate = DateOnly.FromDateTime(DateTime.Today.AddDays(42)),
        MeetingTime = new TimeOnly(9, 0),
        Status = DepartureStatus.Scheduled,
    });
    create.Fields(fields =>
    {
        fields.Add(departure => departure.TripId);
        fields.Add(departure => departure.StartDate);
        fields.Add(departure => departure.MeetingTime);
    });
});
```

## Setting properties that aren't on the form

Some properties need a value when a record is created, but people shouldn't enter it, such as a new departure's status. Set these properties in the factory, and leave them off the form. StellarAdmin saves them with the values the factory set, so you don't need hidden fields. In the example above, the factory sets `Status`, which isn't a field.

A value your database generates, such as an identity key, doesn't need a factory.

## Setting default values that need services

The factory can't use services or asynchronous code. On an EF Core resource, set these defaults in the `OnInitialized` [form event](/docs/admin/form-events) instead. It runs after the factory, before the form is displayed, and receives the new entity in `context.Entity`. The example below starts a new departure with the meeting point of its trip's destination, which it reads from the database:

```cs
resource.AllowCreate(create =>
{
    create.Fields(fields =>
    {
        fields.Add(departure => departure.TripId);
        fields.Add(departure => departure.MeetingPoint);
    });
    create.Events(events =>
        events.OnInitialized = async (context, cancellationToken) =>
            context.Entity.MeetingPoint = await context.Db.Set<Setting>()
                .Select(setting => setting.DefaultMeetingPoint)
                .FirstAsync(cancellationToken)
    );
});
```

StellarAdmin runs `OnInitialized` wherever it displays a create form: on the create page, in a new [inline row](/docs/admin/inline-editing), in the create sheet of a [lookup](/docs/admin/foreign-keys#creating-a-record-from-a-lookup), and in the next form after saving and adding another, before it applies the values that are kept. It doesn't run when someone saves the form, so set values that aren't on the form in `OnCreating`, as described below.

## Generating a unique value, such as a reference

To give each new record a generated value, such as a booking reference, generate it when the record is saved, not in the factory.

StellarAdmin calls the factory twice: when someone opens the create page, and again when they save. A reference that the factory generates randomly therefore gets a different random value on each call. If you display it on the create page, people see one reference, such as "VT-123456", and the booking is saved with another, such as "VT-654321".

On an EF Core resource, generate the value in the `OnCreating` [form event](/docs/admin/form-events), which runs once, before the record is saved:

```cs
resource.AllowCreate(create =>
{
    create.UseFactory(() => new Booking { Reference = "", Status = BookingStatus.Pending });
    create.Fields(fields =>
    {
        fields.Add(booking => booking.TravellerId);
        fields.Add(booking => booking.DepartureId);
    });
    create.Events(events =>
        events.OnCreating = (context, cancellationToken) =>
        {
            context.Entity.Reference = $"VT-{Random.Shared.Next(0, 1_000_000):D6}";

            return Task.CompletedTask;
        }
    );
});
```

With a [custom data source](/docs/admin/custom-data-sources), generate the value in the data source's `CreateAsync()` method, or in a [create handler](/docs/admin/custom-models).
