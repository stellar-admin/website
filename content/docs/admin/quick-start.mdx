This guide builds an admin panel for a travel company, with two resources: customers, and the bookings they make. Before you start, [install StellarAdmin](/docs/admin/installation) and register your EF Core `DbContext` with `AddDbContext()`.

The guide uses the following entities:

```cs
public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Email { get; set; } = "";
    public List<Booking> Bookings { get; set; } = [];
}

public enum BookingStatus { Pending, Confirmed, Cancelled }

public class Booking
{
    public int Id { get; set; }
    public string Reference { get; set; } = "";
    public int CustomerId { get; set; }
    public Customer? Customer { get; set; }
    public DateOnly DepartureDate { get; set; }
    public decimal Total { get; set; }
    public BookingStatus Status { get; set; }
}
```

## Adding customers

Call `AddEfCoreResource()` to register `Customer` as a resource, and add the columns its grid displays. StellarAdmin doesn't add columns automatically, so the grid displays only the columns you add.

```cs
using StellarAdmin;
using StellarAdmin.EntityFrameworkCore;

builder.Services.AddStellarAdmin(admin =>
{
    admin.AddEfCoreResource<Customer>(resource =>
    {
        resource.Index(index => index.Columns(columns =>
        {
            columns.Add(customer => customer.Name);
            columns.Add(customer => customer.Email);
        }));
    });
});
```

Run the application. The sidebar now has a Customers link, which opens the grid at `/stellaradmin/customers`. StellarAdmin finds the `DbContext` that maps `Customer`, and uses the key from the EF Core model.

## Creating and editing customers

A resource's grid is read-only until you allow creating, editing, viewing or deleting records. Call `AllowCreate()` and `AllowEdit()`, and add the fields each form displays.

```cs
admin.AddEfCoreResource<Customer>(resource =>
{
    resource.Index(index => index.Columns(columns =>
    {
        columns.Add(customer => customer.Name);
        columns.Add(customer => customer.Email);
    }));
    resource.AllowCreate(create => create.Fields(fields =>
    {
        fields.Add(customer => customer.Name);
        fields.Add(customer => customer.Email);
    }));
    resource.AllowEdit(edit => edit.Fields(fields =>
    {
        fields.Add(customer => customer.Name);
        fields.Add(customer => customer.Email);
    }));
});
```

The grid now has a Create button, and each row has an Edit action.

<Callout type="idea">
  When the create and edit forms have the same fields, you can [share them in one method](/docs/admin/organizing-configuration#sharing-fields).
</Callout>

## Adding bookings

Each booking belongs to a customer. Because `Customer` is a resource, StellarAdmin renders the `CustomerId` field as a lookup that searches customers, and the `Customer` column displays the customer's name. See [titles and references](/docs/admin/titles-and-references) for how StellarAdmin picks the name.

The example below registers `Booking` with search, sorting, paging, and create, edit and delete.

```cs
admin.AddEfCoreResource<Booking>(resource =>
{
    resource.Index(index =>
    {
        index.Columns(columns =>
        {
            columns.Add(booking => booking.Reference);
            columns.Add(booking => booking.Customer);
            columns.Add(booking => booking.DepartureDate, column => column.Sortable());
            columns.Add(booking => booking.Status);
        });
        index.EnableSearch(term => booking => booking.Reference.Contains(term));
        index.DefaultSortBy(booking => booking.DepartureDate);
        index.EnablePaging();
    });

    resource.AllowCreate(create =>
    {
        create.UseFactory(() => new Booking
        {
            DepartureDate = DateOnly.FromDateTime(DateTime.Today.AddDays(30)),
        });
        create.Fields(fields =>
        {
            fields.Add(booking => booking.Reference);
            fields.Add(booking => booking.CustomerId);
            fields.Add(booking => booking.DepartureDate);
            fields.Add(booking => booking.Total);
        });
    });

    resource.AllowEdit(edit => edit.Fields(fields =>
    {
        fields.AddDisplayField(booking => booking.Reference);
        fields.Add(booking => booking.CustomerId);
        fields.Add(booking => booking.DepartureDate);
        fields.Add(booking => booking.Total);
        fields.Add(booking => booking.Status);
    }));

    resource.AllowDelete();
});
```

In the example above:

- `EnableSearch()` adds a search box to the grid. The expression decides which bookings match the search term. See [search](/docs/admin/search).
- `Sortable()` lets people sort the grid by departure date, and `DefaultSortBy()` sorts by it when the page first loads. See [sorting and paging](/docs/admin/sorting-and-paging).
- `EnablePaging()` splits the grid into pages of 25 bookings.
- `UseFactory()` creates the booking that the create form starts with, so that the departure date starts 30 days from today instead of 0001-01-01.
- `AddDisplayField()` displays the reference on the edit form, without letting people change it.
- `Status` is an enum, so StellarAdmin renders it as a select with an option for each member.
- `AllowDelete()` adds a Delete action to each row, which asks for confirmation first.
