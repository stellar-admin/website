This guide builds an admin panel for a travel company, with two resources: trips, and their departures. Before you start, [install StellarAdmin](/docs/admin/installation) and register your EF Core `DbContext` with `AddDbContext()`.

The guide uses the following entities:

```cs
public class Trip
{
    public int Id { get; set; }
    public required string Code { get; set; }
    public required string Title { get; set; }

    [Display(Name = "Duration (days)")]
    public int DurationDays { get; set; }

    public List<Departure> Departures { get; set; } = [];
}

public enum DepartureStatus { Scheduled, Confirmed, SoldOut, Cancelled }

public class Departure
{
    public int Id { get; set; }
    public int TripId { get; set; }
    public Trip Trip { get; set; } = null!;

    [Display(Name = "Start date")]
    public DateOnly StartDate { get; set; }

    public int Capacity { get; set; }
    public DepartureStatus Status { get; set; } = DepartureStatus.Scheduled;
}
```

A form labels a field with its property's name, so `[Display]` gives `DurationDays` and `StartDate` readable labels. The grid uses the same labels.

## Adding trips

Call `AddEfCoreResource()` to register `Trip` as a resource, and add the columns its grid displays. StellarAdmin doesn't add columns automatically, so the grid displays only the columns you add.

```cs
using StellarAdmin;
using StellarAdmin.EntityFrameworkCore;

builder.Services.AddStellarAdmin(admin =>
{
    admin.AddEfCoreResource<Trip>(resource =>
    {
        resource.Index(index => index.Columns(columns =>
        {
            columns.Add(trip => trip.Code);
            columns.Add(trip => trip.Title);
        }));
    });
});
```

Run the application. The sidebar now has a **Trips** link, which opens the grid at `/stellaradmin/trips`. StellarAdmin finds the `DbContext` that maps `Trip`, and uses the key from the EF Core model.

## Creating and editing trips

A resource's grid is read-only until you allow creating, editing, viewing or deleting records. Call `AllowCreate()` and `AllowEdit()`, and add the fields each form displays.

```cs
admin.AddEfCoreResource<Trip>(resource =>
{
    resource.Index(index => index.Columns(columns =>
    {
        columns.Add(trip => trip.Code);
        columns.Add(trip => trip.Title);
    }));
    resource.AllowCreate(create => create.Fields(fields =>
    {
        fields.Add(trip => trip.Code);
        fields.Add(trip => trip.Title);
        fields.Add(trip => trip.DurationDays);
    }));
    resource.AllowEdit(edit => edit.Fields(fields =>
    {
        fields.Add(trip => trip.Code);
        fields.Add(trip => trip.Title);
        fields.Add(trip => trip.DurationDays);
    }));
});
```

The grid now has a **Create** button, and each row has an edit action, which opens the edit form:

  When the create and edit forms have the same fields, you can [share them in one method](/docs/admin/organizing-configuration#sharing-fields).
</Callout>

## Adding departures

Each departure belongs to a trip. Because `Trip` is a resource, StellarAdmin renders the `TripId` field as a lookup that searches trips, and the `Trip` column displays the trip's title. See [titles and references](/docs/admin/titles-and-references) for how StellarAdmin picks the title.

The example below registers `Departure` with search, sorting, paging, and create, edit and delete.

```cs
admin.AddEfCoreResource<Departure>(resource =>
{
    resource.Index(index =>
    {
        index.Columns(columns =>
        {
            columns.Add(departure => departure.Trip);
            columns.Add(departure => departure.StartDate, column => column.Sortable());
            columns.Add(departure => departure.Capacity);
            columns.Add(departure => departure.Status);
        });
        index.EnableSearch(term => departure => departure.Trip.Title.Contains(term));
        index.DefaultSortBy(departure => departure.StartDate);
        index.EnablePaging();
    });

    resource.AllowCreate(create =>
    {
        create.UseFactory(() => new Departure
        {
            StartDate = DateOnly.FromDateTime(DateTime.Today.AddDays(30)),
        });
        create.Fields(fields =>
        {
            fields.Add(departure => departure.TripId);
            fields.Add(departure => departure.StartDate);
            fields.Add(departure => departure.Capacity);
        });
    });

    resource.AllowEdit(edit => edit.Fields(fields =>
    {
        fields.AddDisplayField(departure => departure.Trip);
        fields.Add(departure => departure.StartDate);
        fields.Add(departure => departure.Capacity);
        fields.Add(departure => departure.Status);
    }));

    resource.AllowDelete();
});
```

The create form starts with a start date 30 days from today, and selects the trip with a lookup:

In the example above:

- `EnableSearch()` adds a [search box](/docs/admin/search) to the grid. The expression decides which departures match the search term, here by their trip's title.
- `Sortable()` lets people [sort the grid](/docs/admin/sorting-and-paging) by start date, and `DefaultSortBy()` sorts by it when the page first loads.
- `EnablePaging()` splits the grid into pages of 25 departures.
- `UseFactory()` creates the departure that the create form starts with, so that the start date starts 30 days from today instead of 0001-01-01.
- `AddDisplayField()` displays the trip on the edit form, without letting people move the departure to another trip.
- `Status` is an enum, so StellarAdmin renders it as a select with an option for each member.
- `AllowDelete()` adds a delete action to each row, which asks for confirmation first.
