title: Images
description: Upload images, and store a reference to them
---

The *image editor* uploads an image, and stores a reference to the image in a `string` property, such as a file name, a storage key or a URL. When someone chooses or drops a file, the editor uploads it straight away, and your code decides where to store it.

To use the image editor, call `UseImageEditor()` and pass `StoreImage()` a function that saves the file.

```cs
using StellarAdmin.Resources.Editors;

fields.Add(destination => destination.Photo).UseImageEditor(image =>
{
    image.StoreImage((file, services, cancellationToken) =>
        services.GetRequiredService<IPhotoStore>().SaveAsync(file, cancellationToken));
});
```

When someone uploads an image, StellarAdmin checks the file's size and type, and then calls the `StoreImage()` function with the uploaded `IFormFile`. The function must save the file and return a `string`, which StellarAdmin stores in the property when the form is saved. The string can't be empty, because an empty value fails the upload.

The example below saves the photo in the app's `wwwroot/photos` folder, and returns the file name:

```cs
public class PhotoStore(IWebHostEnvironment environment) : IPhotoStore
{
    public async Task<string> SaveAsync(IFormFile file, CancellationToken cancellationToken)
    {
        var fileName = $"{Guid.NewGuid()}{Path.GetExtension(file.FileName)}";
        var path = Path.Combine(environment.WebRootPath, "photos", fileName);

        await using var stream = File.Create(path);
        await file.CopyToAsync(stream, cancellationToken);

        return fileName;
    }
}
```

If the property value isn't a URL the browser can load, specify a `ResolveUrl()` function that turns the property value into one.

```cs
using StellarAdmin.Resources.Editors;

fields.Add(destination => destination.Photo).UseImageEditor(image =>
{
    image.StoreImage(...);
    image.ResolveUrl(value => $"/photos/{value}");
});
```

To build the URL with a service registered with dependency injection, pass a function that also takes the services and a cancellation token: `ResolveUrl(async (value, services, cancellationToken) => ...)`.

To display the image in the grid or on the view page, use the [`ImageDisplay`](/docs/admin/image-display) display type, with the same `ResolveUrl()` function.

The record changes only when the form is saved, even though the image uploads straight away. Until then, people can undo replacing or removing the image.

<Callout type="warn">
The image editor needs `StoreImage()`. Without it, StellarAdmin leaves the field off the form, and reports a [configuration problem](/docs/admin/configuration-problems).
</Callout>

## Changing the editor's settings

The example below uses the compact layout for a guide's photo, and accepts files up to 10 MB:

```cs
fields.Add(guide => guide.Photo).UseImageEditor(image =>
{
    image.StoreImage((file, services, cancellationToken) =>
        services.GetRequiredService<IPhotoStore>().SaveAsync(file, cancellationToken));
    image.Layout = ImageEditorLayout.Compact;
    image.MaxFileSize = 10 * 1024 * 1024;
});
```

| Setting | What it does |
| --- | --- |
| `Layout` | Sets how the editor is laid out: `ImageEditorLayout.Dropzone`, a drop zone that displays the image with replace and remove buttons over it; `Compact`, a thumbnail beside upload and remove buttons; or `Attachment`, a row with the thumbnail and the file's name. The default is `Dropzone`. |
| `MaxFileSize` | Sets the largest file the editor accepts, in bytes. The default is 5 MB. |
| `AcceptedTypes` | Sets the media types the editor accepts, such as `image/png`. The default is JPEG, PNG, WebP, GIF and AVIF. To accept SVG files, add `image/svg+xml`. |

The image editor is rendered as an [image upload](/docs/ui/components/image-upload).

In an [inline row](/docs/admin/inline-editing), the image editor is a thumbnail button. If someone saves the row while an image is uploading, StellarAdmin asks them to wait for the upload, and doesn't save the row.

## How uploads are checked

The upload request goes through the resource's authorization and antiforgery checks. StellarAdmin checks the file's size and type again on the server, and recognizes JPEG, PNG, GIF, WebP and AVIF files by their content, so a file that's only been renamed to `.png` is rejected. StellarAdmin raises the request body limit to `MaxFileSize` for the upload request only.

## Deleting images that no record uses

StellarAdmin never deletes images. An image that's replaced or removed, or uploaded on a form that's never saved, stays where `StoreImage()` saved it. To delete the images no record refers to, write your own clean-up code, such as a scheduled job.
