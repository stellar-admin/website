## Introduction

StellarAdmin was born out out my frustration with having to write internal CRUD apps for over 30 years and asking the same question every time - *why isn't there an easier way to do this?*

It is not that these CRUD apps are difficult to write. It is more that they all follow the same predicable pattern and can be mind numbingly boring. You display a list of records, allow a user to add a new record, edit and existing record, and delete the record.

Years ago ASP.NET had a feature called [Dynamic Data](https://learn.microsoft.com/en-us/previous-versions/aspnet/cc488546) which addressed exactly this problem and generated a suite of CRUD pages at runtime from an Entity Framework data context. Sadly, Dynamic Data never made its way across into the ASP.NET Core world.

Most other server web frameworks have products that addresses this gap. Laravel has [Filament](https://filamentphp.com/) and [Nova](https://nova.laravel.com/), and Rails has [Avo](https://avohq.io/). And there are many others on both these and other frameworks. But for some reason ASP.NET Core has nothing that comes close to any of these.

*StellarAdmin is my attempt to address this gap.*

StellarAdmin allows you to rapidly create beautiful, feature rich admin screens for your applications, which still giving you the extensibility to go outside the sandbox of the framework.

## How StellarAdmin works

To create admin pages in StellarAdmin, you register the entities you want to manage as *resources*, and configure how they are displayed. You do all of this in C#, in your app's `Program.cs`.

```cs
builder.Services.AddStellarAdmin(admin =>
{
    admin.AddEfCoreResource<Trip>(resource =>
    {
        resource.Index(index => index.Columns(columns =>
        {
            columns.Add(trip => trip.Title);
            columns.Add(trip => trip.BasePrice);
        }));
        resource.AllowEdit(edit => edit.Fields(fields =>
        {
            fields.Add(trip => trip.Title);
            fields.Add(trip => trip.BasePrice);
        }));
    });
});
```

The code above gives you a **Trips** page at `/stellaradmin/trips` that lists your trips in a grid, and a form to edit them.

StellarAdmin isn't a separate service. It runs inside your application, and uses your app's `DbContext`, services and authentication. It's server-rendered ASP.NET Core MVC, built with the [StellarAdmin.UI](/docs/ui) components, and doesn't use a JavaScript framework or Blazor.

## But AI can create these pages

So one of the questions you may ask is whether something like StellarAdmin still adds value in the age of AI and agents. After all, an AI agent can pump out CRUD screens like this with very little effort.

My answer would be that you are correct. The value of admin frameworks like StellarAdmin are definitely diminished compared to the value they added in a pre-AI world. However, I believe StellarAdmin still adds value for a couple of reasons:

1. With StellarAdmin your agent does not have to write all the CRUD code and page markup. It only has to create the definitions for the various resources and StellarAdmin handles the rest. This ensures more efficient token use and lower cost for you.
2. The above then also leads to the second point which is that StellarAdmin ensures consistency in terms of the UI. Every page will have a consistent user experience in terms on page layout, placements of buttons, etc.

That being said, StellarAdmin fully embraces the new AI world we live in and makes available a full set of [agent skills](/docs/admin/agent-skills) that teaches agents to configure and customize StellarAdmin.
