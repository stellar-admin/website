At some point, most apps need an admin area, often called an admin panel. Somewhere to look up a customer, fix a booking, or take a trip off sale. Building one means writing the same list, create and edit pages over and over, each with its own search box and paging, for every table you want to manage.

StellarAdmin lets you quickly create these admin pages. You register the entities you want to manage as *resources*, and configure how they are displayed. You do all of this in C#, in your app's `Program.cs`.

```cs
builder.Services.AddStellarAdmin(admin =>
{
    admin.AddEfCoreResource<Trip>(resource =>
    {
        resource.Index(index => index.Columns(columns =>
        {
            columns.Add(trip => trip.Name);
            columns.Add(trip => trip.Price);
        }));
        resource.AllowEdit(edit => edit.Fields(fields =>
        {
            fields.Add(trip => trip.Name);
            fields.Add(trip => trip.Price);
        }));
    });
});
```

The example above gives you a **Trips** page at `/stellaradmin/trips` that lists your trips in a grid, and a form to edit them. Each resource you register gets its own link in the sidebar.

StellarAdmin isn't a separate service. It runs inside your application, and uses your app's `DbContext`, services and authentication. It's server-rendered ASP.NET Core MVC, built with the [StellarAdmin.UI](/docs/ui) components, and doesn't use a JavaScript framework or Blazor.

Each field gets an editor based on its type. For example, a `bool` is rendered as a checkbox, an enum as a dropdown, and a foreign key to another resource as a lookup that searches the records of the related resource. You can choose a different [editor](/docs/admin/editors) for any field.

If configuration isn't enough, you can [replace any page](/docs/admin/overriding-pages) with your own Razor view.

## Packages

The `StellarAdmin` package contains the admin panel and everything it needs to manage resources. To manage data in EF Core, add the `StellarAdmin.EntityFrameworkCore` package, which queries and updates data through your `DbContext`.
