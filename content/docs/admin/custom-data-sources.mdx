When your data comes from somewhere other than EF Core, such as an API, a file or another data access library, register the resource with `AddResource<T>()` and give it a data source. The example below registers a `Supplier` resource that a `SupplierDataSource` class loads and saves:

```cs
using StellarAdmin.Resources;

admin.AddResource<Supplier>(resource =>
{
    resource.UseDataSource<SupplierDataSource>();
    resource.UseKey(supplier => supplier.Code);
    resource.Index(index =>
    {
        index.Columns(columns => columns.Add(supplier => supplier.Name, column => column.Sortable()));
        index.EnableSearch();
        index.EnablePaging();
    });
    resource.AllowCreate(create => create.Fields(fields => fields.Add(supplier => supplier.Name)));
    resource.AllowEdit(edit => edit.Fields(fields => fields.Add(supplier => supplier.Name)));
    resource.AllowDelete();
});
```

`UseKey()` sets the property that identifies a record. The edit page, the view page and deleting need a key.

`UseDataSource()` registers the data source as a scoped service, unless you've already registered it, so its constructor can take your own services.

## Implementing the data source

Every data source must implement `IResourceDataSource<T>`, which lists the records for the index page. For everything else you enable, the data source must also implement the matching interface:

| Interface | Methods | Used by |
| --- | --- | --- |
| `IResourceDataSource<T>` | `ListAsync()` | The index page |
| `IResourceCreateHandler<T>` | `CreateAsync()` | The create page |
| `IResourceViewHandler<T>` | `FindAsync()` | The view page |
| `IResourceEditHandler<T>` | `FindAsync()` and `UpdateAsync()` | The edit and view pages |
| `IResourceDeleteHandler<T>` | `DeleteAsync()` | Deleting |

`IResourceCrudDataSource<T>` combines all of these interfaces, for a data source that supports every page. The example below implements `IResourceCrudDataSource<Supplier>` with an API client:

```cs
using StellarAdmin.Resources;

public class SupplierDataSource(SupplierApi api) : IResourceCrudDataSource<Supplier>
{
    public async Task<ResourceListResult<Supplier>> ListAsync(
        ResourceListRequest request, CancellationToken cancellationToken)
    {
        var suppliers = (await api.GetAllAsync(cancellationToken)).AsEnumerable();

        if (request.Keys is { } keys)
            suppliers = suppliers.Where(supplier => keys.Contains(supplier.Code));

        if (request.Search is { } search)
            suppliers = suppliers.Where(supplier =>
                supplier.Name.Contains(search, StringComparison.OrdinalIgnoreCase));

        if (request.Sort is { Field: nameof(Supplier.Name) } sort)
            suppliers = sort.Direction == ResourceSortDirection.Ascending
                ? suppliers.OrderBy(supplier => supplier.Name).ThenBy(supplier => supplier.Code)
                : suppliers.OrderByDescending(supplier => supplier.Name).ThenBy(supplier => supplier.Code);

        var all = suppliers.ToList();
        var page = request.Paging is { } paging
            ? all.Skip((paging.Page - 1) * paging.PageSize).Take(paging.PageSize).ToList()
            : all;

        return new ResourceListResult<Supplier>(page, all.Count);
    }

    public Task<Supplier?> FindAsync(string id, CancellationToken cancellationToken) =>
        api.FindAsync(id, cancellationToken);

    public async Task<ResourceOperationResult> CreateAsync(
        Supplier model, CancellationToken cancellationToken)
    {
        await api.CreateAsync(model, cancellationToken);
        return ResourceOperationResult.Success();
    }

    public async Task<ResourceOperationResult> UpdateAsync(
        string id, Supplier model, CancellationToken cancellationToken)
    {
        if (await api.FindAsync(id, cancellationToken) is null)
            return ResourceOperationResult.NotFound();

        await api.UpdateAsync(id, model, cancellationToken);
        return ResourceOperationResult.Success();
    }

    public async Task<ResourceOperationResult> DeleteAsync(string id, CancellationToken cancellationToken)
    {
        if (await api.HasOpenOrdersAsync(id, cancellationToken))
            return ResourceOperationResult.ValidationFailed(null, "This supplier still has open orders.");

        await api.DeleteAsync(id, cancellationToken);
        return ResourceOperationResult.Success();
    }
}
```

## Filtering, sorting and paging in `ListAsync()`

StellarAdmin doesn't filter, sort or page the records that `ListAsync()` returns, so your data source must do it. StellarAdmin passes the requested search, scope, sort and page, and the keys of the records to return, via the properties of the `request` parameter:

| Property | What it holds |
| --- | --- |
| `Search` | The search text, trimmed, or `null`. |
| `Scope` | The id of the selected [scope](/docs/admin/scopes), or `null`. |
| `Sort` | The `Field` and `Direction` of the sort, or `null`. |
| `Paging` | The `Page`, starting at 1, and the `PageSize`, or `null` to return all matching records. |
| `Keys` | The keys of the only records to return, or `null`. StellarAdmin sets it when [inline editing](/docs/admin/inline-editing) reloads saved rows, and when a lookup loads the records already selected. |

Apply the search, scope and sort before paging. Return the total number of matching records, not only the number on the page.

## Returning results from create, update and delete

`CreateAsync()`, `UpdateAsync()` and `DeleteAsync()` return a `ResourceOperationResult`:

| Result | Meaning |
| --- | --- |
| `Success()` | The record was saved or deleted. |
| `Success(key)` | The record was saved, with the new record's key. Return this from `CreateAsync()` when the create page uses a [custom model](/docs/admin/custom-models), so that a [lookup](/docs/admin/foreign-keys#creating-a-record-from-a-lookup) can select the new record. |
| `NotFound()` | The record doesn't exist any more. |
| `ValidationFailed(field, message)` | The form is displayed again, with the error on that field. Pass `null` as the field for an error that isn't about one field. |

The field name is the model's property name, such as `nameof(Supplier.Name)`. When you return an error, don't save any changes.

For an unexpected failure, throw an exception. The page displays a general error, and StellarAdmin logs the exception.

## Returning validation errors

Some checks can only be made when the data source saves the record, such as checking with the supplier API that a code isn't already in use. To report such a check, return `ValidationFailed()` with the name of the property and the message, and don't save the record. The example below rejects a supplier whose code is already in use:

```cs
public async Task<ResourceOperationResult> CreateAsync(
    Supplier model, CancellationToken cancellationToken)
{
    if (await api.FindAsync(model.Code, cancellationToken) is not null)
        return ResourceOperationResult.ValidationFailed(
            nameof(Supplier.Code), "A supplier with this code already exists.");

    await api.CreateAsync(model, cancellationToken);
    return ResourceOperationResult.Success();
}
```

StellarAdmin displays the error under the field, like any other validation error. If you pass `null` as the property's name, or the property isn't a field of the form, StellarAdmin displays the error for the whole form.

To return several errors at once, pass a list of `ResourceValidationError`s to `ValidationFailed()`.

## Search and scopes without predicates

On a resource with a custom data source, search and scopes don't take predicates, because your data source decides which records match. `index.EnableSearch()` adds the search box, and `ListAsync()` receives the text in `request.Search`. A scope adds a tab, and `ListAsync()` receives its id in `request.Scope`.
