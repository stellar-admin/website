---
title: Defining resources
description: Register the types you manage in the admin panel
---

A *resource* is a type you manage in the admin panel, such as `Trip` or `Booking`. Every resource has an index page that lists its records, and you enable the other pages it needs.

## Adding an EF Core resource

To manage an entity from your `DbContext`, call `AddEfCoreResource<T>()`. The example below adds `Trip` with two columns in the grid and an edit page:

```cs
using StellarAdmin.EntityFrameworkCore;

admin.AddEfCoreResource<Trip>(resource =>
{
    resource.Index(index => index.Columns(columns =>
    {
        columns.Add(trip => trip.Title);
        columns.Add(trip => trip.BasePrice);
    }));
    resource.AllowEdit(edit => edit.Fields(fields =>
    {
        fields.Add(trip => trip.Title);
        fields.Add(trip => trip.BasePrice);
    }));
});
```

StellarAdmin finds the registered `DbContext` that maps `Trip`, and reads the entity's key from the EF Core model. The key must be a single `int`, `long`, `Guid` or `string` property.

If more than one `DbContext` maps the entity, call `UseDbContext<TContext>()` to select the one to use:

```cs
resource.UseDbContext<ApplicationDbContext>();
```

When a column or field displays a related record, such as `booking => booking.Traveller`, StellarAdmin loads the related record in the same query, so you don't need to call `Include()`. Your global query filters still apply.

To manage data that isn't in EF Core, use a [custom data source](/docs/admin/custom-data-sources).

## Adding pages

`Index()` configures the grid on the index page: its columns, search, scopes, sorting and paging. See the [index pages overview](/docs/admin/index-pages).

A resource has no other pages until you enable them:

| Method | Adds |
| --- | --- |
| `AllowCreate()` | A **Create** button on the index page, and a [create page](/docs/admin/forms). |
| `AllowEdit()` | An edit action on each row, and an edit page. |
| `AllowView()` | A view action on each row, and a read-only [view page](/docs/admin/view-pages). |
| `AllowDelete()` | A [delete action](/docs/admin/delete) on each row and on the edit and view pages, which asks for confirmation. |

Each method takes a callback that configures the page or action. To configure the page in separate statements instead, call the method without a callback. It returns the page's builder:

```cs
var create = resource.AllowCreate();
create.Title = "Plan a trip";
create.Fields(fields => fields.Add(trip => trip.Title));
```

## Changing the URL and labels

StellarAdmin derives a resource's URL and labels from its type name:

| Setting | Default | Change it with |
| --- | --- | --- |
| URL slug | The kebab-case plural of the type name: `TripExtra` becomes `trip-extras` | `admin.AddEfCoreResource<TripExtra>("add-ons", resource => ...)` |
| Singular label | The type name, split into words: `TripExtra` becomes `Trip extra` | `resource.SingularLabel = "Add-on";` |
| Plural label | The singular label, pluralized: `Trip extras` | `resource.PluralLabel = "Add-ons";` |

The index page of the `TripExtra` resource is at `/stellaradmin/trip-extras`. Its other pages are at `/stellaradmin/trip-extras/create`, `/stellaradmin/trip-extras/edit/{id}` and `/stellaradmin/trip-extras/view/{id}`.

Page titles and action labels, such as "Create Trip extra" and "Edit Trip extra", use the labels. To change these patterns for every resource, see [global labels](/docs/admin/global-labels).

## Configuring a resource in several places

You can call `AddEfCoreResource<T>()` for the same type more than once. Each call adds to the resource's configuration, and when two calls set the same setting, the later one wins. For example, a shared extension method can set defaults that your app then overrides.

Calling an `Allow*` method again replaces that page's configuration.

A resource keeps the URL slug of the first call. StellarAdmin ignores a slug passed to a later call.
