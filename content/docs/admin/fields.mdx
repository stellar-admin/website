---
title: Fields
description: Editable fields, display fields and read-only values on a form
---

A *field* edits one property of the record on a create or edit page. To add a field, call `Add()` in the `Fields()` callback, with an expression that selects the property. The property must have a public getter and a public setter. If it doesn't have a public setter, StellarAdmin leaves the field out and reports a [configuration problem](/docs/admin/configuration-problems).

StellarAdmin chooses the field's editor from the property's type and attributes. To use a different editor, see [choosing an editor](/docs/admin/editors).

## Configuring a field

`Add()` has two overloads. The example below uses both:

```cs
resource.AllowEdit(edit => edit.Fields(fields =>
{
    fields.Add(booking => booking.CustomerId);
    fields.Add(booking => booking.DepartureDate, field => field.Title = "Departs on");
    fields.Add(booking => booking.Notes).Description = "Only staff see this.";
}));
```

`Add(selector)` returns the field, so you can set its properties or call its methods on the result. `Add(selector, configure)` returns the fields builder instead, so you can't call a field's method on its result. Configure the field in the callback.

## Setting the label and help text

StellarAdmin takes a field's label and help text from the first of these that's set:

| Text | Comes from |
| --- | --- |
| Label | The field's `Title`, then the property's `[Display(Name)]`, then the property's name as written, such as "DepartureDate" |
| Help text | The field's `Description`, then the property's `[Display(Description)]` |

A field that selects a record of another resource, such as `CustomerId`, is labeled with that resource's label, such as "Customer", unless the field sets a `Title` or the property has a `[Display(Name)]`.

To label a field, prefer the `[Display]` attribute on the property over setting `Title`, so that the label and the validation messages use the same name. Validation messages use the name from `[Display]`, such as "The Departure date field is required.", while `Title` changes only the label.

The example below sets the label and the help text of `DepartureDate`:

```cs
public class Booking
{
    [Display(Name = "Departure date", Description = "The first day of the trip.")]
    public DateOnly DepartureDate { get; set; }
}
```

## Displaying values that aren't edited

A *display field* renders a value on the form without an editor. Use it for values nobody edits, such as a reference number or the date a record was created. To add a display field, call `AddDisplayField()`. The example below adds four display fields and one editable field:

```cs
using StellarAdmin.Resources.Displays;

resource.AllowEdit(edit => edit.Fields(fields =>
{
    fields.AddDisplayField(booking => booking.Reference);
    fields.AddDisplayField(booking => booking.CreatedAt, field => field.Title = "Booked on");
    fields.AddDisplayField(booking => booking.Customer!.Email);
    fields.AddDisplayField(booking => booking.Total)
        .UseDisplay<NumberDisplay>(number => number.Format = "C");
    fields.Add(booking => booking.Status);
}));
```

The property of a display field needs only a public getter, and StellarAdmin never saves its value. A display field can select a property of a related record, such as `booking.Customer!.Email`. For an EF Core resource, StellarAdmin loads the related record.

| Setting | What it does |
| --- | --- |
| `Title` | Sets the label. The default is the same as for an editable field. |
| `EmptyText` | Sets the text for an empty value. The default is the property's `[DisplayFormat(NullDisplayText)]`, or a dash. |
| `Orientation` | Places the label above the value with `DisplayFieldOrientation.Vertical`, the default, or beside it with `Horizontal`. |
| `UseDisplay<TDisplay>()` | Renders the value with a different [display type](/docs/admin/displays). |

A display field can also render a value that it computes, such as the price per traveller. A computed value has no property to take its label from, so you must set its `Title`. If you don't, StellarAdmin leaves the field out and reports a [configuration problem](/docs/admin/configuration-problems). The example below computes the price per traveller:

```cs
fields.AddDisplayField(booking => booking.Total / booking.Travellers, field =>
{
    field.Title = "Per traveller";
    field.UseDisplay<NumberDisplay>(number => number.Format = "C");
});
```

## Grouping display fields in a details section

To group display fields under a title, call `AddDetails()` with the section's title. StellarAdmin renders the fields as a list of labels and values. The example below adds a **History** section with two display fields in two columns:

```cs
using StellarAdmin.UI;

fields.AddDetails("History", details =>
{
    details.Columns(2);
    details.Variant = DetailsVariant.Divided;
    details.Add(booking => booking.CreatedAt);
    details.Add(booking => booking.Reference);
});
```

| Setting | What it does |
| --- | --- |
| `Add()` | Adds a display field, with the same settings as `AddDisplayField()`. |
| `Description` | Sets the text below the section's title. |
| `Layout` | Sets the section to one of the [section layouts](/docs/admin/form-layout#choosing-how-sections-look). |
| `Orientation` | Places each label above its value with `DetailsOrientation.Vertical`, the default, or beside it with `Horizontal`. |
| `Variant` | Lays out the fields in a grid with `DetailsVariant.Default`, the default, or in rows with a line between them with `Divided`. |
| `Columns()` | Sets the [number of columns](/docs/admin/form-layout#laying-out-fields-in-columns). |

## Making fields read-only or disabled

To display a field's editor but stop people from changing its value, make the field read-only or disabled. The example below makes `Reference` read-only, makes `Total` read-only once a booking is confirmed, and disables `Notes`:

```cs
resource.AllowEdit(edit => edit.Fields(fields =>
{
    fields.Add(booking => booking.Reference).ReadOnly();
    fields.Add(booking => booking.Total).ReadOnly(booking => booking.Status == BookingStatus.Confirmed);
    fields.Add(booking => booking.Notes).Disabled();
}));
```

| Method | Use it when | The editor |
| --- | --- | --- |
| `ReadOnly()` | The value matters, but can't be changed on this form. | Looks the same as an editable field, and can be focused. |
| `Disabled()` | The field doesn't apply. | Is faded, and is skipped when someone tabs through the form. |

StellarAdmin ignores any value posted for a read-only or disabled field, so nobody can change the value by editing the page's HTML. A field that is both read-only and disabled is disabled.

`ReadOnly(condition)` checks the condition against the record when the form loads, so the field doesn't change while someone edits other fields. A property with `[ReadOnly(true)]` or `[Editable(false)]` is also read-only.

When a value is never edited, use a [display field](#displaying-values-that-arent-edited) instead. Its property doesn't need a setter, and it renders the value with a display type, such as a formatted number.
