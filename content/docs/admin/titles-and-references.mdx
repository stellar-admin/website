---
title: Titles and references
description: Control how a record is named and displayed when other records refer to it
---

Every record has a *title*, which names the record wherever another record refers to it: in a lookup, a select, a grid column or a badge.

## Choosing the title

Unless specified otherwise, the title is the first of these that the resource's type has:

1. The `string` property named by the class's `[DisplayColumn]` attribute.
2. A `string` property called `Name` or `Title`.
3. The key.

For example, a `Customer` with a `Name` property uses the customer's name as its title. To use a different property, call `UseTitle()`:

```cs
admin.AddEfCoreResource<Booking>(resource =>
{
    resource.UseTitle(booking => booking.Reference);
});
```

A record whose title is empty is named by its key.

For an EF Core resource, the title must use only the record's own properties, and EF Core must be able to translate it to SQL. A title that reads a related record isn't loaded for a column. If EF Core can't translate the title, such as one that calls your own method, the title is still displayed, but lookups order the records by key and searches don't match the title. In that case, set `SearchOn()` and `OrderBy()`, as described in [searching, sorting and filtering references](#searching-sorting-and-filtering-references).

## Displaying a description and media

`Reference()` configures how a record is displayed when someone selects it in a lookup or a select. You can add a description, and one kind of media:

```cs
admin.AddEfCoreResource<Customer>(resource =>
{
    resource.Reference(reference => reference
        .UseDescription(customer => customer.Email)
        .UseAvatar(customer => customer.Photo));
});
```

The media methods are `UseIcon()`, `UseAvatar()`, `UseImage()` and `UseCode()`. A lookup whose records have a description displays the selected record as a card.

## Searching, sorting and filtering references

For an EF Core resource, `Reference()` also sets how lookups search and order the records, and which records can be selected:

```cs
resource.Reference(reference => reference
    .SearchOn(customer => customer.Name, customer => customer.Email)
    .OrderBy(customer => customer.Name)
    .Where(customer => !customer.IsBlocked));
```

| Method | Default |
| --- | --- |
| `SearchOn()` | The index page's search, or else the title |
| `OrderBy()` | The index page's default sort, or else the title |
| `Where()` | All records, with your global query filters applied |

`Where()` applies to every field that refers to the resource.

## Access to related records

Selecting a related record doesn't require access to its resource. Someone who can edit bookings can select a customer for a booking, even if they can't manage customers.

See [selecting a related record](/docs/admin/foreign-keys) for the fields that use references.
