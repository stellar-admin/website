title: Scopes
description: Filter the index page with tabs

*Scopes* are tabs above the grid that filter the records, such as **All**, **Pending** and **Confirmed**. One scope is selected at a time.

Call `EnableScopes()`, and add each scope in its callback. The example below adds four scopes to the bookings grid, and selects **All** by default:

```cs
resource.Index(index =>
{
    index.EnableScopes(scopes =>
    {
        scopes.Add("all", "All");
        scopes.Add("pending", "Pending", booking => booking.Status == BookingStatus.Pending);
        scopes.Add("confirmed", "Confirmed", booking => booking.Status == BookingStatus.Confirmed);
        scopes.Add("cancelled", "Cancelled", booking => booking.Status == BookingStatus.Cancelled);
        scopes.DefaultScope = "all";
    });
});
```

`Add()` takes these arguments:

1. The scope's id, which the URL uses, as in `?scope=pending`. Each scope must have a different id.
2. The text of the scope's tab.
3. For an EF Core resource, the filter. Leave it out for a scope that displays every record. A custom data source takes no filter, because it [filters the records itself](#scoping-a-custom-data-source).

Only the filter decides which records a scope displays. The id is only a name, so `scopes.Add("pending", "Pending")` on an EF Core resource displays every record.

## Setting the default scope

`DefaultScope` sets the scope that's selected when the URL doesn't name a scope. Without a default scope, no tab is selected, and the grid displays every record until someone selects a scope. In most cases, set the scope that displays every record as the default.

`DefaultScope` must be the id of a scope you've added. If it isn't, StellarAdmin ignores it and reports a [configuration problem](/docs/admin/configuration-problems).

## Combining scopes with search

StellarAdmin applies both the scope's filter and the [search](/docs/admin/search), so searching on the **Pending** tab searches only the pending bookings.

## Restricting which records people can access

Scopes don't restrict access to records. Anyone who can access the index page can select any scope by changing the URL. To hide records from some users, use an EF Core global query filter or a [custom data source](/docs/admin/custom-data-sources).

## Scoping a custom data source

When a resource uses a [custom data source](/docs/admin/custom-data-sources), add each scope without a filter, such as `scopes.Add("pending", "Pending")`. StellarAdmin passes the id of the selected scope via the `Scope` property of the `request` parameter when calling the `ListAsync()` method.

## Filtering by a field

Scopes are the only filters StellarAdmin supports. Filters on a field, such as a date range or a select, aren't supported yet.
