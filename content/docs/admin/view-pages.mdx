A resource's *view page* displays one record without editing it. To add the page, call `AllowView()` on the resource. The example below adds a view page for bookings, with a **Trip** section and a **Traveller** section:

```cs
using StellarAdmin.Resources.Displays;

resource.AllowView(view => view.Fields(fields =>
{
    fields.Columns(2);
    fields.AddSection("Trip", section =>
    {
        section.Add(booking => booking.Reference);
        section.Add(booking => booking.Departure.Trip);
        section.Add(booking => booking.Departure.StartDate);
        section.Add(booking => booking.Passengers.Count, field => field.Title = "Travelers");
        section.Add(booking => booking.TotalAmount, field =>
            field.UseDisplay<NumberDisplay>(number => number.Format = "C"));
    });
    fields.AddSection("Traveller", section =>
    {
        section.Add(booking => booking.Traveller);
        section.Add(booking => booking.Traveller.Email, field => field.Title = "Email");
        section.Add(booking => booking.SpecialRequests, field => field.EmptyText = "No special requests");
    });
}));
```

When a view page is enabled, the index page displays a view button on each row. The view page's header has a **Back** button that returns to the index page. If the resource has an edit page, the header also has an **Edit** button, and if [deleting is enabled](/docs/admin/delete), a **Delete** button.

StellarAdmin doesn't add fields automatically, so the page displays only the fields you add. If the page has no fields, StellarAdmin leaves out the page and the view buttons, and reports a [configuration problem](/docs/admin/configuration-problems).

## Adding fields

Every field on a view page is a [display field](/docs/admin/fields#displaying-values-that-arent-edited), so it has the same settings, such as `Title`, `EmptyText` and `UseDisplay()`. A field can select a property of a related record, such as `booking.Traveller.Email`, or compute a value. A field that selects a record of another resource, such as `booking.Traveller`, displays that record's title.

## Laying out the page

A view page uses the same [sections, groups and columns](/docs/admin/form-layout) as a form, and the same [section layouts](/docs/admin/form-layout#choosing-how-sections-look), which you set with the page's `SectionLayout`.

To display each label beside its value instead of above it, set a section's `Orientation` to `FieldOrientation.Horizontal`. A field's own `Orientation` overrides its section's. The example below displays the **Audit** section's labels beside their values:

```cs
using StellarAdmin.UI;

resource.AllowView(view => view.Fields(fields =>
{
    fields.AddSection("Audit", section =>
    {
        section.Orientation = FieldOrientation.Horizontal;
        section.Add(booking => booking.BookedAt);
        section.Add(booking => booking.UpdatedAt);
    });
}));
```

## Changing the title

The page's title defaults to "View" and the singular label, such as "View Booking". To change it, set `Title` in the `AllowView()` callback:

```cs
resource.AllowView(view =>
{
    view.Title = "Booking details";
    view.Fields(fields => fields.Add(booking => booking.Reference));
});
```

To change the default for every resource, see [global labels](/docs/admin/global-labels).

## Displaying a different model

To display something other than the resource's entity, such as a summary that combines several records, give the page its own model and a *handler* that loads it. Call `AllowView()` with the model and the handler as type arguments:

```cs
resource.AllowView<BookingSummary, BookingSummaryHandler>(view => view.Fields(fields =>
{
    fields.Add(summary => summary.Reference);
    fields.Add(summary => summary.Itinerary);
}));
```

The handler implements `IResourceViewHandler<T>`. Its `FindAsync()` method loads the model for the record with the given key. Return `null` when the record doesn't exist, and StellarAdmin returns a 404. StellarAdmin registers the handler as a scoped service, unless you've registered it already, so the handler can take any service in its constructor.

Without a handler, StellarAdmin loads the record through the resource's data source, which an EF Core resource already does. A [custom data source](/docs/admin/custom-data-sources) must implement `IResourceViewHandler<T>`, which `IResourceEditHandler<T>` includes. If it doesn't, StellarAdmin leaves out the page and reports a configuration problem.

## Adding content to the page

To add content the fields can't display, such as a list of related records or a button in the header, [override the page](/docs/admin/overriding-pages) and use its [slots](/docs/admin/page-tag-helpers).
