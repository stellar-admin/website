By default, a create or edit page edits the resource's entity, and saves it through the resource's data source. When the form doesn't match the entity, give the page its own *form model*, and a *handler* that saves it. For example, signing up a customer needs a password and a confirmation, which the `Customer` entity doesn't store.

## Using a form model on the create page

To use a form model on the create page, call `AllowCreate()` with the form model and the handler as type arguments. The example below adds a create page that signs up a customer:

```cs
resource.AllowCreate<NewCustomerForm, NewCustomerHandler>(create => create.Fields(fields =>
{
    fields.Add(form => form.Name);
    fields.Add(form => form.Email);
    fields.Add(form => form.Password);
    fields.Add(form => form.ConfirmPassword);
}));
```

The form model has a property for each field, with the attributes that validate it:

```cs
public class NewCustomerForm
{
    [Required]
    public string Name { get; set; } = "";

    [Required, EmailAddress]
    public string Email { get; set; } = "";

    [Required, DataType(DataType.Password)]
    public string Password { get; set; } = "";

    [Compare(nameof(Password)), DataType(DataType.Password)]
    [Display(Name = "Confirm password")]
    public string ConfirmPassword { get; set; } = "";
}
```

The handler implements `IResourceCreateHandler<T>`. When someone saves the form, StellarAdmin calls the handler's `CreateAsync()` method with the form model. The example below rejects an email address that's already used, and otherwise saves the customer and sets the password:

```cs
using StellarAdmin.Resources;

public class NewCustomerHandler(VoyagerDbContext db, CustomerAccounts accounts)
    : IResourceCreateHandler<NewCustomerForm>
{
    public async Task<ResourceOperationResult> CreateAsync(
        NewCustomerForm form, CancellationToken cancellationToken)
    {
        if (await db.Customers.AnyAsync(customer => customer.Email == form.Email, cancellationToken))
            return ResourceOperationResult.ValidationFailed(
                nameof(NewCustomerForm.Email), "A customer with this email already exists.");

        var customer = new Customer { Name = form.Name, Email = form.Email };
        db.Customers.Add(customer);
        await db.SaveChangesAsync(cancellationToken);
        await accounts.SetPasswordAsync(customer, form.Password, cancellationToken);

        return ResourceOperationResult.Success(customer.Id.ToString());
    }
}
```

StellarAdmin registers the handler as a scoped service, unless you've registered it already, so the handler can take any service in its constructor. The handler replaces only the data source's create. The page's title and labels still come from the resource.

Return the new record's key with `Success(key)`. StellarAdmin can't read the key from a form model, and a [lookup](/docs/admin/foreign-keys#creating-a-record-from-a-lookup) that opens the create page needs the key to select the new record. To reject the form, return [validation errors](/docs/admin/custom-data-sources#returning-validation-errors) the same way a data source does.

StellarAdmin creates the form model with its parameterless constructor. To start it with other values, call [`UseFactory()`](/docs/admin/default-values).

A field with `[DataType(DataType.Password)]` is always empty when the form is displayed, so when the form has errors, people enter the password again.

## Using a form model on the edit page

To use a form model on the edit page, call `AllowEdit()` with the form model and the handler as type arguments:

```cs
resource.AllowEdit<CustomerProfileForm, CustomerProfileHandler>(edit => edit.Fields(fields =>
{
    fields.Add(form => form.Name);
    fields.Add(form => form.Email);
}));
```

The handler implements `IResourceEditHandler<T>`, which has two methods:

- `FindAsync()` loads the form model for the record with the given key. Return `null` when the record doesn't exist, and StellarAdmin returns a 404.
- `UpdateAsync()` saves the form model to the record with the given key. Return `NotFound()` when the record doesn't exist any more, such as when someone deleted it while the form was open.

When someone saves the form, StellarAdmin calls `FindAsync()` again, applies the posted fields to the form model, and passes it to `UpdateAsync()`. A property that isn't on the form keeps the value `FindAsync()` loaded. The example below loads and saves a customer's name and email address:

```cs
using StellarAdmin.Resources;

public class CustomerProfileHandler(VoyagerDbContext db) : IResourceEditHandler<CustomerProfileForm>
{
    public async Task<CustomerProfileForm?> FindAsync(string id, CancellationToken cancellationToken)
    {
        var customer = await db.Customers.FindAsync([int.Parse(id)], cancellationToken);
        return customer is null ? null : new CustomerProfileForm { Name = customer.Name, Email = customer.Email };
    }

    public async Task<ResourceOperationResult> UpdateAsync(
        string id, CustomerProfileForm form, CancellationToken cancellationToken)
    {
        var customer = await db.Customers.FindAsync([int.Parse(id)], cancellationToken);
        if (customer is null)
            return ResourceOperationResult.NotFound();

        customer.Name = form.Name;
        customer.Email = form.Email;
        await db.SaveChangesAsync(cancellationToken);
        return ResourceOperationResult.Success();
    }
}
```

StellarAdmin passes the record's key to both methods, so the form model doesn't need a key property.

## Running your own code when a record is saved

StellarAdmin has no events that run before or after a record is saved. To run your own code when a record is saved, such as sending an email or writing an audit entry, do it in a handler.

When the form matches the entity, the form model can be the entity itself. For example, the create handler in [generating a unique value](/docs/admin/default-values#generating-a-unique-value-such-as-a-reference) saves a `Booking`, and sets the booking's reference first.

## Binding a field with your own code

A *field binder* reads a field's value and applies the posted values with your own code, instead of through the property. Use one for a property without a public setter, such as a read-only list, or when the posted values aren't the property's value. EF Core resources already use a field binder for [many-to-many](/docs/admin/many-to-many) fields, so you'll mostly need your own with a [custom data source](/docs/admin/custom-data-sources).

In the example below, `Supplier` has a list of region codes without a setter:

```cs
public class Supplier
{
    public string Code { get; set; } = "";
    public string Name { get; set; } = "";
    public List<string> Regions { get; } = [];
}
```

A field binder inherits from `FieldBinder`. Its `GetValue()` method returns the value the field's editor displays, and its `BindAsync()` method applies the posted values to the model. The example below fills the list from the posted values:

```cs
using StellarAdmin.Resources;

public class RegionsBinder : FieldBinder
{
    public override object? GetValue(FieldBindingContext context) =>
        ((Supplier)context.Model).Regions.ToList();

    public override Task BindAsync(FieldBindingContext context, CancellationToken cancellationToken)
    {
        var regions = ((Supplier)context.Model).Regions;
        regions.Clear();
        regions.AddRange(context.Values.Where(value => !string.IsNullOrEmpty(value))!);
        return Task.CompletedTask;
    }
}
```

To use the binder, call `UseBinder()` on the field's options after StellarAdmin has configured the resource. The example below uses `RegionsBinder` for the `Regions` field on the create and edit pages:

```cs
using StellarAdmin.Resources.Options;

builder.Services.AddOptions<ResourceOptions<Supplier>>().PostConfigure(options =>
{
    var fields = (options.Create?.Fields ?? []).Concat(options.Edit?.Fields ?? []);
    foreach (var field in fields.Where(field => field.FieldName == nameof(Supplier.Regions)))
        field.UseBinder(new RegionsBinder());
});
```

StellarAdmin uses one instance of the binder for every request, so get services from `context.Services`, not from the constructor. To display an error under the field, call `context.AddError()` with the message.
