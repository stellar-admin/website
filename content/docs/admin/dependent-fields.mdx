---
title: Filtering options by another field
description: Make a field's options depend on the value of another field, such as the cities of the selected country
---

A field's options can depend on the value of another field on the same form, such as a city that must be in the selected country. To make a field depend on another field, call `DependsOn()` on it, and filter its options by the other field's value.

The example below registers countries and cities as resources, and lists only the cities of the selected country in the city field's lookup:

```cs
admin.AddEfCoreResource<Country>(resource => { /* ... */ });
admin.AddEfCoreResource<City>(resource => { /* ... */ });

fields.Add(destination => destination.CountryId);

fields.Add(destination => destination.CityId)
    .DependsOn(destination => destination.CountryId)
    .UseLookupSheetEditor(lookup =>
    {
        lookup.UseResource<City>(items => items.Where((city, destination) =>
            city.CountryId == destination.CountryId));
    });
```

`Where()` receives each record and the form's model, and returns whether the record is an option. Only an EF Core resource can apply the filter. On a resource with a [custom data source](/docs/admin/custom-data-sources), StellarAdmin ignores the filter, and reports a configuration problem.

When people change the country, the city field loads its options again, and clears its value. While no country is selected, the city field is disabled, and displays "Select Country first", named after the label of the country field.

`DependsOn()` works with every choice editor and lookup, on the create and edit pages, and in [inline rows](/docs/admin/inline-editing). To make a field depend on several fields, call `DependsOn()` once for each of them. A field can also depend on a field that depends on another, such as a neighborhood that depends on the city.

## Reading other fields in the filter

The `destination` instance passed to the filter contains only the values of the fields named in `DependsOn()`, and the record's key on the edit page. Every other property has its default value, such as `null`, `0` or `false`.

So if the filter reads another property, call `DependsOn()` for that field too. Otherwise the filter reads the property's default value instead of the value on the form. The example below lists only the cities with an airport when **Requires airport** is checked, so the city field depends on both fields:

```cs
fields.Add(destination => destination.CityId)
    .DependsOn(destination => destination.CountryId)
    .DependsOn(destination => destination.RequiresAirport)
    .UseLookupSheetEditor(lookup =>
    {
        lookup.UseResource<City>(items => items.Where((city, destination) =>
            city.CountryId == destination.CountryId
            && (!destination.RequiresAirport || city.HasAirport)));
    });
```

## Choosing which fields a field depends on

A field can only depend on an editable field of the same form. If it depends on any other field, or if two fields depend on each other, StellarAdmin ignores the dependency, and reports a [configuration problem](/docs/admin/configuration-problems).

## Changing the text of a disabled dependent field

While a field it depends on has no value, a dependent field is disabled, and displays a text that asks for that value first, such as "Select Country first". To change this text, set `EmptyText` in the callback of `DependsOn()`. The example below changes the text the city field displays while no country is selected:

```cs
fields.Add(destination => destination.CityId)
    .DependsOn(destination => destination.CountryId, country =>
    {
        country.EmptyText = "Select a country to see its cities";
    })
    .UseLookupSheetEditor(/* ... */);
```

## Loading options that depend on another field from a service

When the options come from your own code, a choice editor's `UseItems()` takes a function that receives the form's model, the request's services and a cancellation token, and returns the options. StellarAdmin doesn't call the function while a field it depends on has no value.

The example below loads the cities of the selected country from a `CityDirectory` service:

```cs
using StellarAdmin.Resources.Editors;

fields.Add(destination => destination.CityId)
    .DependsOn(destination => destination.CountryId)
    .UseSelectEditor(select =>
    {
        select.UseItems(async (destination, services, cancellationToken) =>
        {
            var cities = await services.GetRequiredService<CityDirectory>()
                .ListAsync(destination.CountryId, cancellationToken);

            return cities
                .Select(city => new ChoiceItem(city.Id.ToString(), city.Name))
                .ToList();
        });
    });
```

For a lookup, derive the [lookup source](/docs/admin/foreign-keys#selecting-records-from-another-service) from `LookupSource<TItem, TValue, TArgument>`, where `TArgument` is the type of the value the search takes from the form. Its `SearchAsync()` receives that value before the query:

```cs
using StellarAdmin.Resources.Editors;

public class CountryAirportSource(AirportClient client) : LookupSource<Airport, string, int>
{
    public override string GetValue(Airport airport) => airport.Code;

    public override string GetTitle(Airport airport) => airport.City;

    public override Task<IReadOnlyCollection<Airport>> FindAsync(
        IReadOnlyCollection<string> values,
        CancellationToken cancellationToken)
    {
        return client.FindAsync(values, cancellationToken);
    }

    public override async Task<LookupPage<Airport>> SearchAsync(
        int countryId,
        LookupQuery query,
        CancellationToken cancellationToken)
    {
        var airports = await client.SearchAsync(
            countryId, query.Term, query.Skip, query.Take + 1, cancellationToken);

        return new LookupPage<Airport>(
            airports.Take(query.Take).ToList(),
            airports.Count > query.Take);
    }
}
```

To pass the value, call `UseSource()` with an expression that reads it from the form's model:

```cs
fields.Add(guide => guide.HomeAirport)
    .DependsOn(guide => guide.CountryId)
    .UseLookupSheetEditor(lookup =>
    {
        lookup.UseSource<CountryAirportSource>(guide => guide.CountryId);
    });
```

The value must have the type of `TArgument`, or its nullable type. If the search needs several values, pass a record that holds them.

## Validating the selected option

The filter only limits the options people can select. StellarAdmin doesn't check that the saved value matches the filter, such as that the city is in the selected country. If that matters, [validate the form](/docs/admin/validation) yourself.

`DependsOn()` only changes a field's options. It can't make a field read-only or disabled as the fields it depends on change.
