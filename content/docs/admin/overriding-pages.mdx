---
title: Overriding pages
description: Replace a page of the admin panel with your own Razor view
---

StellarAdmin renders each page of the admin panel with a Razor view that's compiled into the `StellarAdmin` package. To override a page, add a view with the same path to your app. As with any Razor class library, ASP.NET Core uses your app's view instead of the package's.

Most of the time, you'll keep StellarAdmin's content and add your own around it, such as a summary above the grid of an index page.

## Adding the view imports [#view-imports]

StellarAdmin's own `_ViewImports.cshtml` is compiled into the package, so it doesn't apply to your views. Before you override a page or a template, add a `_ViewImports.cshtml` to your app's `Areas/StellarAdmin/Views/` folder that imports StellarAdmin's namespaces and Tag Helpers:

```razor title="Areas/StellarAdmin/Views/_ViewImports.cshtml"
@using StellarAdmin
@using StellarAdmin.UI
@using StellarAdmin.Areas.StellarAdmin
@using StellarAdmin.Areas.StellarAdmin.ViewModels
@using Voyager.Models
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
@addTagHelper *, StellarAdmin.UI
@addTagHelper *, StellarAdmin
```

Replace `Voyager.Models` with the namespace of your own models. If the folder has no `_ViewImports.cshtml`, Razor doesn't process tags such as `<sa-index-page>`, and writes them to the page as plain HTML. The page then looks empty where the tag is, without an error.

## Overriding a resource's page

To override a page of one resource, add a view named after the page, in a folder named after the resource's [slug](/docs/admin/resources#changing-the-url-and-labels). The view's model depends on the page:

| Page | View | Model |
| --- | --- | --- |
| Index | `Areas/StellarAdmin/Views/{slug}/Index.cshtml` | `ResourceIndexPageViewModel<TResource>` |
| Create | `Areas/StellarAdmin/Views/{slug}/Create.cshtml` | `ResourceFormPageViewModel` |
| Edit | `Areas/StellarAdmin/Views/{slug}/Edit.cshtml` | `ResourceFormPageViewModel` |
| View | `Areas/StellarAdmin/Views/{slug}/View.cshtml` | `ResourceViewPageViewModel` |

For example, the index page of a resource with the `bookings` slug is `Areas/StellarAdmin/Views/bookings/Index.cshtml`. The folder name ignores case, so `Views/Bookings/` works too.

To override a page for all resources, add `ResourceIndex.cshtml`, `ResourceCreate.cshtml`, `ResourceEdit.cshtml` or `ResourceView.cshtml` to `Areas/StellarAdmin/Views/Shared/`. The model of `ResourceIndex.cshtml` is `IResourceIndexPageViewModel`, because the view is used for resources of different types. A view in a resource's folder overrides the shared view for that resource.

## Adding content to a page

Your view renders StellarAdmin's content of the page with the page's [Tag Helper](/docs/admin/page-tag-helpers), such as `<sa-index-page>`, and adds its own content around it.

The example below displays the number of bookings that are waiting for confirmation above the grid of the bookings index page:

```razor title="Areas/StellarAdmin/Views/bookings/Index.cshtml"
@model ResourceIndexPageViewModel<Booking>
@using Microsoft.EntityFrameworkCore
@inject VoyagerDbContext Db
@{
    ViewData["Title"] = Model.Title;
    var pending = await Db.Bookings.CountAsync(booking => booking.Status == BookingStatus.Pending);
}

<sa-page-container>
    <sa-alert>
        <sa-alert-title>@pending bookings are waiting for confirmation</sa-alert-title>
    </sa-alert>
</sa-page-container>

<sa-index-page model="Model" />
```

Set `ViewData["Title"]` to `Model.Title`, as StellarAdmin's own views do, so the browser tab displays the page's title. `Model.Items` contains only the records on the current page of the grid, so count totals with your own query, as in the example above.

Search, scopes, sorting and paging still work on an overridden index page. They replace only the grid, and leave your content as it is.

To add content inside the page, such as a button next to **Create**, use the [slots](/docs/admin/page-tag-helpers#slots) of the page's Tag Helper.

## Keeping the Delete button on the edit page

StellarAdmin's edit view adds the **Delete** button and its confirmation dialog itself, not `<sa-form-page>`. If you override the edit page and [deleting is enabled](/docs/admin/delete), add both to your view:

```razor title="Areas/StellarAdmin/Views/bookings/Edit.cshtml"
@model ResourceFormPageViewModel
@{
    ViewData["Title"] = Model.Title;
}

<sa-form-page model="Model">
    @if (Model.Delete is { } delete)
    {
        <sa-slot-content name="form-leading-actions">
            <sa-button type="button" variant="ButtonVariant.Destructive"
                       command="show-modal" commandfor="delete-confirm-dialog">@delete.Title</sa-button>
        </sa-slot-content>
    }
</sa-form-page>

@if (Model.Delete is not null)
{
    <partial name="_FormDeleteDialog" model="Model.Delete" />
}
```

The view page's **Delete** button is part of `<sa-view-page>`, so an overridden view page keeps it.

## Overriding other parts of the admin panel

You can also override these views:

- The [home page](/docs/admin/home-page), with `Areas/StellarAdmin/Views/Home/Index.cshtml`.
- The editors and displays, the environment indicator, the [sidebar header](/docs/admin/branding#replacing-the-top-of-the-sidebar) and the [user menu](/docs/admin/user-menu#replacing-the-user-menu). See [overriding templates](/docs/admin/template-overrides) for their paths.
