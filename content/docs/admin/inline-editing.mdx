*Inline editing* allows users to edit records inline in the grid without navigation to another page. The works well with resources that contains only around 2 to 4 fields and allows for rapid data entry.

<Screenshot name="inline-editing-edit-row" alt="The destinations grid with one row being edited, with a name input, a country lookup, a featured checkbox and Save and Cancel buttons, and the other rows dimmed" todo="Crop of the destinations grid configured as above, with the second row being edited." />


To edit records inline, call `UseInlineRow()` in the `AllowEdit()` callback. The example below edits the name, country and featured flag of a destination inline:

```cs
using StellarAdmin.Resources;

admin.AddEfCoreResource<Destination>(resource =>
{
    resource.Index(index => index.Columns(columns =>
    {
        columns.Add(destination => destination.Name);
        columns.Add(destination => destination.Country!.Name, column =>
        {
            column.Title = "Country";
            column.EditsField(destination => destination.CountryId);
        });
        columns.Add(destination => destination.IsFeatured);
    }));

    resource.AllowEdit(edit =>
    {
        edit.Fields(fields =>
        {
            fields.Add(destination => destination.Name);
            fields.Add(destination => destination.CountryId);
            fields.Add(destination => destination.IsFeatured);
        });
        edit.UseInlineRow();
    });
});
```

When the user clicks a row's edit action, the row's cells change to editors, and **Save** and **Cancel** buttons replace the row actions. Press <kbd>Enter</kbd> in an input, or <kbd>Ctrl</kbd>+<kbd>Enter</kbd> (<kbd>Command</kbd>+<kbd>Enter</kbd> on a Mac) in any field, to save the row. Press <kbd>Esc</kbd> to cancel the edits.

## Configuring the edited row

You configure the edited row using the inline edit builder. By default, other rows are dimmed once you start editing and inline row. The example below keeps the rest of the page usable while a row is edited.

```cs
edit.UseInlineRow(inline =>
{
    inline.DimOtherRows = false;
});
```

| Setting | Description |
| --- | --- |
| `DimOtherRows` | Determines whether the user is prevented from editing other rows while editing a row inline. When `true`, the default, StellarAdmin dims and locks the rest of the page while the row is edited. When `false`, editing another row cancels the first one. |
| `AfterSave` | Determines the grid's behaviour [when a row is saved](#choosing-what-happens-after-a-save). `ReloadGrid` (the default) will reload the entire grid after saving a record. This may be jarring to the user as the record may disappear from the page due to sorting or filtering rules. You can prevent this by using `KeepInPlace`. |

## Matching fields to columns

Since the grid's columns and the edit page's fields are defined independently, you need to take care to ensure that the index columns and the edit fields match. 

When the inline editing mode is enabled, StellarAdmin attempts to match each field in the edit form with a column mapped to the same field. The editor for the field is then displayed in the matching grid column. A column without a matching edit field displays its value and the user won't be able to edit it.

When a column displays a different property than the field it edits, such as the country's name for the `CountryId` field, call `EditsField()` on the column to name the field.

```cs
columns.Add(destination => destination.Country!.Name, column =>
{
    column.Title = "Country";
    column.EditsField(destination => destination.CountryId);
});
```

If a field doesn't have a column, StellarAdmin turns off editing for the resource, because saving the row could leave out that field's value. It reports a [configuration problem](/docs/admin/configuration-problems) that names the field.

## Use inline editing for adding records

You can also enable inline creation of new records in the grid by calling `UseInlineRow()` in the `AllowCreate()` callback. 

<Screenshot name="inline-editing-new-row" alt="A new, empty row at the bottom of the destinations grid, with Featured already checked" todo="Crop of the bottom of the destinations grid after clicking the Create button in the grid, with the configuration above. Box around the new row." />

The example below enables adding new records via an inline row and removes the **Create** button from index page header in favour of an inline button directly on the grid. It also initializes each new record with the specified default values using `UseFactory()`.

```cs
resource.AllowCreate(create =>
{
    create.Fields(fields =>
    {
        fields.Add(destination => destination.Name);
        fields.Add(destination => destination.CountryId);
        fields.Add(destination => destination.IsFeatured);
    });
    create.UseFactory(() => new Destination { Name = "", IsFeatured = true });
    create.UseInlineRow(inline =>
    {
        inline.AddButton = InlineAddButton.Grid;
    });
});
```
<Callout>
    Every `[Required]` property of the model must have a field. If one doesn't, StellarAdmin turns off creating records, and reports a configuration problem.
</Callout>

The `UseInlineRow()` method returns a builder that allows you to configure the behaviour of the row.

| Setting | What it does |
| --- | --- |
| `Position` | Adds the new row at the `Top` of the current page (the default) or at the `Bottom`. |
| `AddButton` | Specifies whether the **Create** button must be displayed in the page `Header` as usual, in a row of the `Grid`, or in `Both` (the default). |
| `DimOtherRows` | When `true` (the default), StellarAdmin dims and locks the rest of the page while the row is open. When `false`, opening another row cancels the first one. |
| `AfterSave` | Determines the [grid's behaviour after a new row is saved](#choosing-what-happens-after-a-save). `ReloadGrid` reloads the entire grid, but this can be jarring to the user as the sorting and filtering rules may mean the record disappears from its position.`KeepInPlace` keeps displaying the new record in the same position that the new row appeared. |

To speed up data entry, call [`EnableAddAnother()`](/docs/admin/forms#saving-and-adding-another-record) on the create page. The new row then has a third button, which saves the row and opens another new row. Pressing <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Enter</kbd> (<kbd>Command</kbd>+<kbd>Shift</kbd>+<kbd>Enter</kbd> on a Mac) does the same.

## Choosing what happens after a save

`AfterSave` sets what the grid does after a row is saved:

- `ReloadGrid` reloads the current page of the grid, with its search, scope, sort and page, so that the saved row moves to where it belongs. If the saved row isn't on the page any more, a message says so.
- `KeepInPlace` keeps the saved row where it is until the grid next reloads. It suits entering several records quickly into a short list.

## Editors that work in a cell

Not every [editor](/docs/admin/editors) works in a cell:

| Editor | Method | Works in a cell |
| --- | --- | --- |
| Text input, including number, email and the other single-line inputs | `UseTextInputEditor()` | <Yes /> |
| Select | `UseSelectEditor()` | <Yes /> |
| Checkbox | `UseCheckboxEditor()` | <Yes /> |
| Switch | `UseToggleEditor()` | <Yes /> |
| Date input | `UseDateInputEditor()` | <Yes /> |
| Date and time input | `UseDateTimeInputEditor()` | <Yes /> |
| Time input | `UseTimeInputEditor()` | <Yes /> |
| Segmented control | `UseSegmentedControlEditor()` | <Yes /> |
| Lookup | `UseLookupSheetEditor()` | <Yes /> |
| List | `UseListEditor()` | <Yes /> |
| Dictionary | `UseDictionaryEditor()` | <Yes /> |
| Image | `UseImageEditor()` | <Yes /> |
| Icon | `UseIconEditor()` | <Yes /> |
| Textarea | `UseTextareaEditor()` | <No /> |
| Rich text | `UseRichTextEditor()` | <No /> |
| Radio group | `UseRadioGroupEditor()` | <No /> |
| Checkbox group | `UseCheckboxGroupEditor()` | <No /> |
| Toggle group | `UseToggleGroupEditor()` | <No /> |
| Slider | `UseSliderEditor()` | <No /> |
| One-time code | `UseOneTimeCodeEditor()` | <No /> |
| Multi-lookup | `UseMultiLookupSheetEditor()` | <No /> |

In Development, a cell with an editor that doesn't work in a cell displays an error that names the missing template. Saving the row leaves the value of that field unchanged.

A [custom editor](/docs/admin/custom-editors) works in a cell once you add a template for it to `GridEditorTemplates/`.

## Changing the labels

To change the labels and messages of inline rows, set these properties in the `Index()` callback:

| Property | Default |
| --- | --- |
| `SaveLabel` | "Save" |
| `CancelLabel` | "Cancel" |
| `CreatedMessage` | The singular label and "added", such as "Destination added" |
| `SavedMessage` | The singular label and "saved", such as "Destination saved" |
| `NotShownMessage` | "It isn't on this page with the current search, scope and sort." |

To change the defaults for every resource, see [global labels](/docs/admin/global-labels).
