## Usage

`<sa-icon-picker>` edits a string that holds the name of an icon. Bind it with `asp-for`, or give it a `name` and `value`, and list the icons it offers as child [`<sa-icon>`](/docs/ui/components/icon) elements. Each child names a registered icon, and only its `name` is used. Search matches the names and the icons' keywords, which the built-in Lucide and Tabler icons include.

```razor
<sa-icon-picker asp-for="...">
    <sa-icon name="..." />
</sa-icon-picker>
```

The button shows the current icon and its name. It opens a popover with a search box, a grid of the icons and a status line that names the icon under the pointer and counts the matches. The current icon comes first. Choosing an icon closes the popover and puts its name in a hidden input, which is what the form posts. A field that isn't required offers Clear in the status line.

The current icon is rendered on the server, so the value shows before the script runs. A stored name that isn't one of the icons still shows, with a dashed box in place of the icon, and posts unchanged. Check a newly chosen name on the server, since a request can post any value.

## Examples

### Inline

Set `layout` to `IconPickerLayout.Inline` to show every icon as a tile, chosen with one click, without a popover. It suits a short list of a couple of dozen icons at most. The tiles are a single-select [toggle group](/docs/ui/components/toggle-group), so they work without the script. An optional field is cleared by clicking the chosen tile again, which needs the script.

### Icons from a URL

To offer a large set, such as every registered icon, give `icons-url` instead of child icons. The picker requests the URL once, when it first opens, and searches and scrolls through the whole set in the browser, rendering more icons as the grid scrolls. A form that is never opened makes no request. `icons-url` can't be combined with child icons or the inline layout.

## The icons endpoint

The picker sends a GET request to `icons-url`, with no query string, and expects JSON:

```json
{
  "icons": [
    { "name": "wifi", "svg": "<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 24 24\" …>…</svg>", "keywords": ["internet", "wireless"] }
  ]
}
```

`name` and `svg` are required, and `keywords` is optional. Search matches the names and the keywords. `svg` is complete markup with an `<svg>` root, so the icons can come from any source, not only `IconOptions`. The picker skips an entry whose markup has another root, and removes scripts, `foreignObject`, event attributes and `javascript:` links before showing it. If the request fails, the popover says so and the picker tries again the next time it opens.

This endpoint returns every registered icon from `IconOptions`:

```csharp
public IActionResult OnGetIcons([FromServices] IOptions<IconOptions> iconOptions)
{
    var icons = iconOptions.Value;
    var payload = icons.GetIconNames().Order(StringComparer.Ordinal).Select(name =>
    {
        icons.TryGetIcon(name, out var icon);
        return new { name, svg = ToSvg(icon!), keywords = icon!.Keywords };
    });

    return new JsonResult(new { icons = payload });
}

private static string ToSvg(IconDefinition icon)
{
    var svg = new StringBuilder("<svg");
    foreach (var (name, value) in icon.Attributes)
    {
        svg.Append($" {name}=\"{WebUtility.HtmlEncode(value)}\"");
    }

    svg.Append('>');
    foreach (var shape in icon.Shapes)
    {
        svg.Append($"<{shape.Name}");
        foreach (var (name, value) in shape.Attributes)
        {
            svg.Append($" {name}=\"{WebUtility.HtmlEncode(value)}\"");
        }

        svg.Append("/>");
    }

    return svg.Append("</svg>").ToString();
}
```

The whole Lucide set, with keywords, is about 1 MB of JSON, and about 150 KB compressed, so enable response compression, or serve a precompressed copy, and let browsers cache the response. Put a version in the URL, such as a hash of the icons, when the set can change.

## Accessibility

The button announces the current icon's name and opens a dialog popover. In the popover, the search box has focus first. ↓ moves from the search box into the grid, the arrow keys move between icons, Enter chooses the focused icon and ↑ from the first row returns to the search box. In the search box, Escape first clears the search and then closes the popover. The status line is a polite live region that announces the number of matches. Focus returns to the button when the popover closes.

`aria-label` and `aria-describedby` on `<sa-icon-picker>` are passed to the button, or to the toggle group with the inline layout. Inline tiles are named by their icon's name.

## Part classes

Pass an `IconPickerClassNames` instance from the `StellarAdmin.UI` namespace using `class-names`. Each property accepts an optional string of space-separated CSS classes, which are added to the part's existing classes.

| Property | Target |
| --- | --- |
| `Root` | The generated field wrapper, when the control renders an implicit field. |
| `Label` | The generated field label, when rendered. |
| `Description` | The generated help text, when rendered. |
| `Error` | The generated validation message element, when rendered. |
| `Content` | The generated container around the label and supporting text in a horizontal implicit field. |
| `Control` | The picker's container. |
| `Trigger` | The button that opens the popover. |
| `Popover` | The popover. |
| `Item` | Each tile of an inline picker. |

Root, Label, Description, Error, and Content are inherited from `FieldClassNames`; see [Field part classes](field#part-classes).
