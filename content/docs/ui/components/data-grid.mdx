The data grid is part of `StellarAdmin.UI` and uses the standard tag helper setup, theme stylesheet, and JavaScript bundle.

## Setup

Register the tag helpers alongside your application's MVC or Razor Pages services:

```csharp
builder.Services.AddStellarAdminUI();
```

Add these directives to `_ViewImports.cshtml`:

```razor
@using StellarAdmin.UI
@addTagHelper *, StellarAdmin.UI
```

## Row details

Add an `<sa-data-grid-row-detail>` to let rows expand and show more information below them. Its content is a row template like a column's `<sa-data-grid-item-template>`: it renders once per row, with the row's item available through `Html.GridItem<T>()`, so the details can show more fields of the same item or rows from another source, such as the itinerary in a nested grid here. The grid adds a column of toggles, with an expand-all toggle in its header. To render rows expanded, set `key-field` to the property that identifies a row and `expanded-keys` to the keys of the rows to open.

<Demo src="/demo/ui/data-grid-row-details.html">
  <include>./_include/data-grid-row-details.mdx</include>
</Demo>

The details use the same behavior and events as [table row details](/docs/ui/components/table#row-details), including loading them with htmx. To place the toggle yourself, such as in an actions column beside an edit button, set `toggle="DataGridRowDetailToggle.None"` and add an `<sa-table-row-detail-toggle>` to that column's `<sa-data-grid-item-template>`. The `emphasis`, `divider` and `inset` settings look as they do on a table; see the [row details divider](/docs/ui/components/table#row-details-divider) example.

## Inline editing

Rows can be edited in place. Set `key-field` to the property that identifies a row, and list the keys of the rows to edit in `editing-keys`. Those rows render each column's `<sa-data-grid-edit-template>` instead of its value, with the row's item available through `Html.GridItem<T>()`; a column without an edit template keeps showing its value. Any number of rows can be in edit mode at once, and selection and row details keep working.

<Demo src="/demo/ui/data-grid-editing.html">
  <include>./_include/data-grid-editing.mdx</include>
</Demo>

Fields in an editing row are named after the row's key, so `asp-for="@Html.GridItem<Booking>().Destination"` posts as `rows[TRP-4822].Destination`. Bind a row's values with that prefix, for example `await TryUpdateModelAsync(booking, $"rows[{key}]")`. Give an editor the `sa-cell-editor` class so it fills its cell without changing the row's height, wrap a switch or checkbox in a `<span class="sa-cell-check">`, and label each editor with `aria-label`, since the cell has no label of its own. While a row is in edit mode the columns keep their widths, so the grid doesn't shift as editors appear.

## New row

Pass an item to `new-item` to render it as a new row in edit mode, above the other rows. Its key is `new`, so its fields post as `rows[new].Destination`. Columns without an edit template are empty in the new row.

## Add row

An `<sa-data-grid-add-row>` renders a full-width row for a button that adds an item, first in the grid or, with `position="DataGridAddRowPosition.Bottom"`, last. It also shows when the grid has no items, in which case the empty-state message steps aside for an added row, and it hides while a new row (the key `new`) is in edit mode.

## Validation errors

Render the posted values again with the errors under their cells: add an `<sa-field-error class="sa-cell-error">` for each field. It shows only when the field is invalid, and model state errors are keyed by the prefixed name, such as `rows[TRP-4822].Amount`.

## Row requests with htmx

The grid renders only what it is given, so the requests that edit, save and add rows are the application's. Render the same grid with `rows-only="true"` for a row request: it returns only the rows, without the grid, its table and its header, so a response can replace a single `<tr>`. A row rendered in edit mode this way has no details row; the row it replaced keeps its own.

- **Edit:** load the item and render it with its key in `editing-keys`, swapped in for the row with `hx-target="closest tr" hx-swap="outerHTML"`.
- **Save:** post the row's fields with `hx-include="closest tr"`, since a form can't hold a table row, and send the antiforgery token in `hx-headers`. On success, render the saved item as a display row; on failure, render the editing row again with the errors. For a row whose details row stayed in the page, select only the row with `hx-select="tr[data-key]"` and refresh the details' content with `hx-select-oob`.
- **Add:** render the new item with `new-item` and insert the row where it belongs, for example with `hx-swap="afterend"` from a button in an add row.
- **Cancel:** mark the button `data-row-cancel`. The grid puts the row it replaced back without a request, or removes a new row. Only a row that was rendered in edit mode with the page has no row to restore, so its Cancel button goes to the server.

```razor
@inject Microsoft.AspNetCore.Antiforgery.IAntiforgery Antiforgery
@{
    var headers = $$"""{"RequestVerificationToken": "{{Antiforgery.GetAndStoreTokens(Context).RequestToken}}"}""";
}

<sa-data-grid-edit-template>
    <sa-button variant="ButtonVariant.Outline" size="ButtonSize.Small" data-row-cancel
               hx-get="?handler=Cancel&id=@Html.GridItem<Tour>().Id" hx-target="closest tr" hx-swap="outerHTML">Cancel</sa-button>
    <sa-button size="ButtonSize.Small" hx-post="?handler=Save&id=@Html.GridItem<Tour>().Id"
               hx-include="closest tr" hx-headers="@headers" hx-target="closest tr" hx-swap="outerHTML">Save</sa-button>
</sa-data-grid-edit-template>
```
